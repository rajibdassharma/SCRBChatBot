Embedding Migration Plan — Ollama to sentence-transformers

ISD Document Intelligence V5 | Objective: Faster bulk indexing by bypassing Ollama HTTP overhead | Date: March 2026

1. Why This Change?

Factor Ollama Embeddings (Current) sentence-transformers (Proposed)
How it works Python → HTTP call → Ollama server → GPU → return vector Python → GPU directly → return vector
Batching One chunk per HTTP call 256+ chunks per GPU call
Overhead per chunk 200–500ms (HTTP + serialization) <5ms (direct GPU)
7,929 SMAC files estimated time 24–48 hours 30–60 minutes
Read Timeouts Frequent on large files (9–11 pages) None — no HTTP involved
GPU utilization Low (idle between HTTP calls) High (continuous batch processing)
Model used mxbai-embed-large (via Ollama) mixedbread-ai/mxbai-embed-large-v1 (same model)
Vector dimensions 1024 1024 (identical)
Internet required No (model already in Ollama) Only once to download model (~670 MB), then fully offline

2. Accuracy Assurance

There is ZERO impact on accuracy.

Reason: Ollama's mxbai-embed-large is a repackaged version of HuggingFace's mixedbread-ai/mxbai-embed-large-v1. They share the same neural network weights. Given the same input text, both produce the same 1024-dimensional vector. The only difference is the transport layer (HTTP vs direct GPU call).

What affects accuracy (all unchanged):
  • Chunk size (2000 words) — unchanged
  • Embedding model — unchanged (same model, same weights)
  • LLM model (gemma3:12b / llama3.3:70b) — unchanged
  • Search algorithm (Vector + BM25 + RRF fusion) — unchanged
  • System prompts — unchanged
  • ChromaDB storage — unchanged
  • MySQL structured data — unchanged
